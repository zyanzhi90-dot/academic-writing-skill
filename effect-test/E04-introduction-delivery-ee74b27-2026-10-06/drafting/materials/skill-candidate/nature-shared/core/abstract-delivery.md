# Abstract delivery: source-grounded Polishing

Use this procedure for a complete abstract drafted from author material or
submitted for unrestricted polishing. Section fragments own contribution and
evidence selection; `scientific-expression.md` owns the expression checks.
This file specifies how to execute those checks against the source.
Respect a narrower author-requested edit scope.

## Handoff

For autonomous abstract delivery, preserve the working Drafting output, then
run a distinct `nature-polishing` pass with that draft, the original author
facts, requirements, and selected reference passages. Use a fresh context when
the execution environment supports it. Do not pass the drafter's self-assessment
as evidence of correctness or require sentence-level author feedback. Polishing
owns the checked delivery; a working draft and a checked abstract have separate
status. For an existing abstract, start directly with Polishing.

## Source-to-prose check

After reading the draft, reopen the original author scientific material. Build
a compact internal source-to-prose map, not a checklist answered from memory:

- For each scientific assertion in the draft, locate its author-source support
  and compare the actual technical category, action, object, scope and strength.
  An established draft term or Terminology Ledger entry is revisable when the
  original facts show it is wrong. Preserve category-defining modifiers when
  shortening or translating; a familiar broader name is not automatically an
  equivalent name.
- In the other direction, map the selected contributions from the original
  facts into the paragraph. For each retained key design, identify the task
  need, enabling action or information, and supported effect. Check the adjacent
  sentences for the relation needed to explain that effect, including its
  input/output handoff or the object of an estimation or compensation action
  when applicable. An implementation convenience alone may not explain the
  design's purpose. This map selects necessary relations, not every source detail.
- Attach a model assumption or guarantee condition to the assertion it limits.
  An author note cannot supply a condition necessary for a reader of the abstract
  to interpret that assertion. Keep implementation requirements distinct from
  proof assumptions; do not expand either into a proof inventory.
- For each verification item, record the contribution it supports and what
  would become unsupported or materially different if that item were removed.
  Combine or remove items with the same support function, including a summary
  followed by the same result unpacked as settings or curve directions. Retain
  a separate finding when it supplies independent necessary evidence or a
  consequential boundary. Preserve the source-specific scope when combining.

Repair determinate mismatches and missing necessary relations using the selected
references' actual consecutive sentences and ordinary English. Then compare the
repaired phrases and their local context with the source-to-prose map and run
the shared expression check. Follow the author's length requirement; otherwise
use the selected abstracts' information load to trim excess. Preserve mature
wording and reasonable variants. Report only genuinely unresolved scientific
questions outside the abstract; do not defer a source-resolvable error to
manual revision. The map is internal unless an execution record or the author
requests it.
